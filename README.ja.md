# Mozu

<p align="center">
  <a href="README.md">English</a> |
  <a href="README.ja.md">日本語</a>
</p>

修飾キーの一回押しで入力ソースを切り替える Mac 用メニューバー常駐アプリです。
JISキーボードには「かな」「英数」キーがありますが、中国語やその他の言語に切り替えるボタンはありません。
USキーボードで日本語と英語を切り替えるアプリには有名な[英かな](https://github.com/KS1019/eikana) があります。これを中国語やその他の言語でも使えるようにしたくて作りました。

名前のmozuは鳥のモズのことです。モズは百舌鳥（百の舌を持つ鳥）という名前のとおり、他の鳥の鳴き真似が上手だそうです。

![demo](docs/assets/mozu-demo.mp4)

## 設計方針（なぜトグルではないか）

中国語では一般的にShiftキーで中英の入力を切り替えます。
中国語の時には英語に、英語の時は中国語に。
しかしShiftでの中英トグルは「今どの言語になっているか」を画面を見て確認しなければなりません。
確認のために視点を動かすと、そこに意識が飛んで思考が途切れます。

そこで Mozu は**絶対指定**だけを提供することにしました。

- 割り当てたキーを離した瞬間に状態が決まる（現在の状態によって結果が変わらない）
- すでに同じソースが選ばれていれば、そのまま何もしない
- 既存のショートカット（`Cmd+C` など）には干渉しない

## Homebrew（このリポジトリが tap を兼ねる）

```sh
brew tap nicokinu/mozu https://github.com/nicokinu/mozu.git
brew install mozu
open "$(brew --prefix mozu)/Mozu.app"
```

formula はユーザーのマシンでビルドするので、生成物に quarantine が付きません
（SwiftPM の依存がゼロなのでビルドにネットワークも要らない）。

## zip によるインストール（GitHub Releases）

リリースページから `Mozu-vX.Y.Z.zip` をダウンロードして `Mozu.app` を `/Applications` へ。

ad-hoc 署名なので、ブラウザでダウンロードしたものは初回のダブルクリックだと
「開発者を確認できません」で開けません。どちらかで通ります:

- Finder で **右クリック → 開く**（1 回だけ）
- ターミナルで `xattr -dr com.apple.quarantine /Applications/Mozu.app`

brew 版と zip 版は bundle id と designated requirement が同じなので、
macOS 的には同じアプリとして扱われ、差し替えても許可はそのままです。

## 必要権限（両方必須）

| 権限 | 役割 |
|---|---|
| 入力監視 | キー入力の観測。無いと変換中のタイピングが黙って見えない |
| アクセシビリティ | イベントタップを張ることと、確定キー（英数/かな/Return）の注入 |

⚠️ **「入力監視」は許可ダイアログが出ません。** 設定ウィンドウの「許可する…」で
システム設定が開くので、Mozu のスイッチを**手動で ON** にしてください。
アクセシビリティだけだと切り替え自体は動くのに変換中の確定だけが黙って壊れる
というわかりにくい壊れ方をするため、Mozu は両方が揃ってから監視を開始します。

## 初回起動

1. メニューバーのアイコン → **設定…**
2. 「状態」の**アクセシビリティ**と**入力監視**を許可する
3. 「キー割り当て」で各キーに入力ソースを選ぶ
4. **ログイン時に起動** を ON に

メニューにソースが何も並ばないときは、システム設定 → キーボード → 入力ソースで
使う言語を追加しておく必要があります（`TISSelectInputSource` は追加済みのものしか選択できない）。

### 設定例

```
左 Command  → 英語 (ABC)
右 Command  → 日本語 (ひらがな)
左 Option   → 簡体字中国語 (ピンイン)
右 Option   → 繁体字中国語 (注音/ピンイン)
左/右 Control → （予備スロット）
```

割り当てはメニューから自由に変更できます。

ことえりのローマ字入力とかな入力のように、**別々の入力ソースが同じ表示名を持つ**
ことがあります（どちらも「ひらがな」）。その場合は自動で接尾辞を添えて区別します
（`ひらがな（ローマ字入力）` / `ひらがな（かな入力）`）。

## 変換中の文字列について

変換中（未確定）のまま別の言語に切り替えると、IME は変換中文字列を
確定ではなく「棚上げ」で保持し、あとで同じソースに戻した瞬間に再出現して
混乱の原因になります。Mozu はこれを避けるため、IME 系ソースから離れる直前に
確定キーを 1 発注入してから切り替えます（日本語は英数キー、中国語は Return）。

その副作用として、日本語から離れるときにカーソル横のインジケーターが
「ABC → 目標言語」と**2 回パチパチ表示されます**。これは仕様です。
英数確定をやめると表示は 1 回で済みますが、確定が未完のまま切り替わる
競争が復活して裏残りのバグが再発します。見た目ではなくデータのほうを
取った結果です。

## トラブルシューティング

システム設定のスイッチが ON なのに許可が通っていないように動くときは:

```sh
tccutil reset Accessibility com.nico.mozu
tccutil reset ListenEvent com.nico.mozu   # 入力監視
```

で許可を初期化して、両方許可し直してください。
通常の再ビルドでは許可は外れません（署名に cdhash 非依存の指定要件を
埋め込んでいるため。詳しくは [docs/DESIGN.md](docs/DESIGN.md)）。

## ビルド

```sh
./Scripts/build-app.sh
open build/Mozu.app
```

`swift build` でもデバッグビルドできるが、メニューバー常駐として正しく動かすには
`.app` バンドルにする（`LSUIElement` と安定した bundle id が必要）。

## 対応言語

UI の対応言語は **ja / en / zh-Hans / zh-Hant の 4 種のみ**。
開発言語を `en` にしてあるため、未知の言語環境では英語にフォールバックします。

## なぜこういう設計か

英かなとの違い、変換中文字列の棚上げの仕組み、イベントタップの階層、
TCC の識別、メニューが AppKit の理由、リリース手順などは
[docs/DESIGN.md](docs/DESIGN.md) にまとめてあります。
